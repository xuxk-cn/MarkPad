# MarkPad 启动与使用手册

> 本文面向使用者与贡献者，说明如何安装、启动与使用 **MarkPad**。架构与路线图见 `docs/开发方案讨论稿.md`；简要运行命令见 **`RUN.md`**；根目录 **`README.md`** / **`使用手册.md`** 为项目简介与用户简明手册。

---

## 1. 软件简介

**MarkPad** 是基于 **Tauri v2** 的 Windows 桌面 Markdown 编辑器，强调：

- **一体化编辑**：同一区域编辑 Markdown 源码，叠加层呈现标题、列表等基础样式（类 Typora，**无分栏预览**）。
- **Rust Rope** 作为文档单一事实源，配合 **`pulldown-cmark`** 块级解析。
- **轻量前端**：TypeScript + 原生 DOM + Vite，无 React/Vue 整页壳。

---

## 2. 环境要求

| 组件 | 说明 |
|------|------|
| **Node.js** | ≥ 18（推荐 LTS） |
| **Rust** | stable 工具链（`rustup` 安装） |
| **操作系统** | Windows 10/11；需 **WebView2**（Win11 已内置，部分 Win10 需单独安装 Runtime） |

## 3. 安装与首次启动

在 **PowerShell** 中进入项目根目录（请按你的实际路径修改）：

```powershell
cd E:\projects\MarkPad
npm install
npm run tauri dev
```

执行过程说明：

1. **`npm install`**：安装前端与 `@tauri-apps/cli` 等开发依赖。
2. **`npm run tauri dev`**：首次会编译 Rust 依赖，可能耗时数分钟；随后启动 Vite（默认 `http://localhost:1420`）并打开应用窗口。

关闭应用窗口即退出；终端中可按 `Ctrl+C` 结束开发进程。

## 4. 界面与基本操作

### 4.1 主界面

- **标题栏左侧**：应用 Logo 与当前文件名（已保存路径显示为「文件名 — MarkPad」，未保存为「未命名 — MarkPad」）。
- **标题栏右侧**：
  - **最近…**：下拉选择最近打开过的文件路径（最多 10 条，存于本机浏览器 `localStorage`）。
  - **打开**：系统文件对话框，选择 `.md` / `.markdown` / `.txt` 等。
  - **保存**：写入当前路径；若无路径则弹出「另存为」。
  - **复制**：将当前文档全文复制到剪贴板（Markdown 源码）。

### 4.2 编辑区

- **底层**：可编辑的 Markdown 源码（文字在界面上为透明，仅光标与选区可见）。
- **叠加层**：根据语法渲染标题、段落、列表、引用、代码块等；**不可点击**，鼠标与键盘作用于底层源码。

输入后内容会同步到 Rust 侧 Rope；**较长文档**（块数或 UTF-8 体积超过阈值）会启用**视口切片**：只渲染可见附近的块，并在下一帧用测量结果校正上下占位高度，使叠加层总高度与可滚动区域一致，避免向下滚动时下方「看不见」格式化内容。

### 4.3 长文档滚动验收（可选）

发版或合并前建议手动确认：

1. `npm run tauri dev`，打开一篇较长 `.md`（多章节或数千行以上）。
2. 将滚动条拖到约 **50%**、**90%** 文档高度：标题与段落样式应连续可见，无大块空白。
3. 快速甩动滚动条数次：叠加层应能跟上，无长时间整屏空白。

自动化：`npm run test` 中含视口 spacer 相关单测。

## 5. 快捷键

| 快捷键 | 作用 |
|--------|------|
| **Ctrl+S** | 保存 |
| **Ctrl+O** | 打开文件 |
| **Ctrl+F** | 打开/聚焦查找条 |
| **Esc** | 关闭查找条 |
| **Enter**（在查找框内） | 执行搜索 |
| **F3** | 跳到下一处搜索结果 |

查找由 **Rust 命令 `doc_search`** 在全文上扫描子串，结果条数显示在查找条右侧；「下一个」或 F3 会按大致行位置滚动编辑区（超长文档为近似滚动）。

## 6. 自动保存（Obsidian 式）

当文档**已关联磁盘路径**（通过「打开」或首次「另存为」指定过 `.md` 等文件）时：

- 编辑内容会先同步到应用内的文档缓冲区（Rope），在**停止输入约 1.2 秒**后，会自动写回当前文件，**无需反复按保存**。
- 另有约 **30 秒一次**的兜底落盘，避免极端情况下长时间未写入。
- **未命名**、尚未指定保存路径的笔记**不会**自动写到磁盘；需使用 **保存** 或 **Ctrl+S** 选择路径后，才会开始自动保存到该文件。

仍可在任意时刻使用 **Ctrl+S** 立即保存（含首次指定路径）。

## 8. 生产构建与安装包

```powershell
cd E:\projects\MarkPad
npm run tauri build
```

默认在项目根执行 `npm run tauri build` 时，产物在 `src-tauri/target/release/`（安装包在其中的 `bundle/`，依 `tauri.conf.json` 而定）。若使用 **`scripts/build-non-standalone.bat`** 或 **`scripts/build-portable-no-installer.bat`**，脚本会将 `CARGO_TARGET_DIR` 设为项目根 **`output`**，则产物在 **`output/release/`**。安装包脚本在成功后 **只保留 `bundle/`**（根目录 exe 等会删掉）；便携脚本 **只保留 exe 与 dll**。两者在构建成功后会 **自动** 调用同目录 **`scripts/clean-pack-release.bat`** 完成上述精简，**无需**再单独运行清理脚本。若环境异常导致产物仍落在 `src-tauri/target/release/`，批处理会尝试检测并 **回退清理** 该目录并打印警告。完整说明见 **`docs/打包说明.md`**。首次 release 编译时间较长。

## 9. 开发者常用命令

在项目根目录执行：

| 命令 | 说明 |
|------|------|
| `npm run check` | TypeScript 类型检查（`tsc --noEmit`） |
| `npm run build` | 类型检查 + Vite 生产构建 |
| `npm run test` | 前端单元测试（Vitest，`src/**/*.test.ts`） |
| `cd src-tauri; cargo test` | Rust 单元测试 |
| `npm run test:all` | 依次执行 `check`、前端 `test`、Rust `cargo test` |
| `npm run bench` | Rust 性能基准（`perf_10k`，需 `src-tauri` 下环境正常） |

## 10. 常见问题

- **cargo 下载慢**：可在用户目录下配置国内 crates 镜像（参见 `RUN.md` 中的示例 `config.toml`）。
- **端口 1420 被占用**：同时修改 `vite.config.ts` 中的 `server.port` 与 `src-tauri/tauri.conf.json` 中的 `build.devUrl`，保持一致。
- **WebView2 缺失**：从微软文档安装 [WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/)。
- **复制失败**：确认系统允许应用访问剪贴板；在 Tauri/WebView2 环境下一般无需额外权限。
