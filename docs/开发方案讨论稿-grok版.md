**我的极简 Markdown 编辑器开发方案（推荐版）**

### 1. 核心目标（不变，但更明确）

- **性能第一**：输入延迟接近原生文本编辑器（目标 < 16ms 95 分位），显著优于 Typora。
- **资源极致**：冷启动 < 300ms，空闲内存 < 80MB，长文档（10万行）编辑态 < 250MB，二进制体积 < 15MB（目标）。
- **体验**：Typora 式「源码 + 所见即所得一体化」（优先），专注写作，无干扰。
- **原则**：极简、克制、长期可维护。只做 20% 最核心功能，做到 80% 用户 95% 的使用场景完美。

---

### 2. 技术栈最终推荐

**主路线：Tauri 2 + Rust 重后端 + 轻量前端**

- **后端（Rust）**：
  - 文件 I/O、内存映射大文件
  - Rope 结构（`ropey` 或 `xi-rope`）作为核心文本缓冲
  - Markdown 解析（`pulldown-cmark` + 自定义增量扩展）
  - 搜索、设置、最近文件、clipboard 图片处理等
- **前端**：
  - **Svelte 5**（或 SvelteKit）—— 极致轻量、响应式开销低
  - 编辑器：**CodeMirror 6**（Markdown 模式 + 自定义扩展）
  - 预览：自定义块级渲染（避免巨型 DOM）
- **为什么不 Electron**：体积和内存直接被 Tauri 吊打。
- **备选纯原生路线**（如果想极致）：Rust + egui / iced + 自研文本编辑器（长期更优，但首期不推荐）。

**跨平台**：Windows / macOS / Linux（Web 版后续按需）。

---

### 3. 核心架构（我的优化版）

#### 3.1 编辑模型
- **单一真理源**：Rust 侧 Rope 文本缓冲区（支持高效插入、删除、undo/redo）。
- **光标与选中**：前端 CodeMirror 负责，但变更同步到 Rust 后端。
- **一体化所见即所得**：
  - **源码主导 + 叠加层**：编辑器底层是纯 Markdown 源码，在源码上方用绝对定位或内容可编辑叠加层渲染富格式（标题加大、列表 bullet 替换、图片实时显示等）。
  - Typora 经典体验，同时避免富文本的布局灾难。

#### 3.2 Markdown 渲染管线（性能关键）
- **块级增量解析**：只解析修改的块 + 相邻 1-2 个块（通过空行、标题等边界快速定位）。
- **预览更新**：
  - 修改后立即在 Worker 中异步解析变更块。
  - 使用 `requestIdleCallback` + 优先级队列。
  - 只更新 DOM 中对应块（虚拟 DOM 或 细粒度 Svelte 组件）。
- **虚拟化渲染**：只挂载视口 ± 2 屏的块，其余用占位 div（高度预计算）。
- **代码高亮**：仅视口内 + 变更块，使用 `highlight.js` 或 `shiki`（Rust 侧也可）。
- **长文档策略**：大文件使用内存映射 + 懒解析，只加载视口附近 AST。

---

### 4. 功能范围（极简 MVP → V1）

**MVP（目标 6-8 周上线）**
- 打开、保存、自动保存（UTF-8）
- 一体化编辑 + 实时预览（源码模式切换作为保底）
- 基础语法：标题、列表、引用、任务列表、代码块、链接、图片（本地相对路径）
- 图片拖拽 & 粘贴（保存到 `./assets/` 或同级文件夹）
- 浅色 + 深色两套固定主题（CSS 变量）
- 最近文件列表、本地搜索
- 导出：复制为 HTML、单文件 HTML
- 基础设置（字体、字号、行距、主题）

**V1（再 4-6 周）**
- 大纲侧栏（基于块 AST，实时）
- 表格增强、脚注
- 简单禅模式（全屏 + 打字机滚动）
- 命令面板（Cmd/Ctrl + P）
- PDF 导出（Rust 侧或 wkhtmltopdf）

**明确不做（首版）**：插件系统、云同步、数学公式、Mermaid、主题市场、协作、版本历史可视化。

| ---------- | --------------- | ------------------- |

### 6. 开发里程碑

**阶段 0（1-2 周）：技术验证**
- Tauri 模板 + CodeMirror 6 + Rust Rope + 简单块级解析
- 准备 10 万行测试文档（中英文、列表、代码块混合）
- 压测全量 vs 增量渲染，验证延迟

**阶段 1（MVP，6-8 周）**
- 完整文件操作 + 一体化编辑 + 基础预览
- 主题 + 导出 + 设置

**阶段 2（V1，打磨，4-6 周）**
- 大纲、图片增强、性能专项优化、跨平台适配

**阶段 3**：社区反馈、长期迭代

---

### 7. 风险与对策

- **一体化复杂度**：MVP 先确保分栏完美，再全力做一体化。若时间紧，先上线「源码 + 右侧实时预览」作为正式版。
- **中文输入法**：早期重点测试（Windows + macOS），必要时在 Rust 侧做输入事件优化。
- **跨平台一致性**：使用系统 WebView，重点测字体渲染和滚动行为。
- **维护性**：严格控制前端依赖（≤ 15 个包），核心逻辑放在 Rust。

---

### 8. 额外亮点想法（低成本高价值）

- **打字机滚动**（光标始终在屏幕中间）
- **专注模式**（自动隐藏侧边栏）
- **智能粘贴**（自动识别 URL 转链接、图片自动保存）
- **本地全文模糊搜索**（Rust 侧极快）
- **键盘全覆盖 + 可选 Vim 模式**

**总结**：

这个方案在你原方案基础上，进一步强化了 **Rust 后端 + Rope + 块级增量 + CodeMirror + Svelte** 的组合，性能天花板更高，同时保持了极简主义。

我认为**Tauri 这条路线是当前性价比最高的选择**，既能快速出 MVP，又有足够空间做到“吊打 Typora 性能”的程度。
