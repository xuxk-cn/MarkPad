### 2026-05-10 — 方案文档

- 确立方向：打造**响应快、占用低**、类 Typora 但**功能克制**的 Markdown 编辑器；初版讨论稿写入 `docs/开发方案讨论稿.md`。

  **结论**：不就「站队某一稿」定稿，而从两稿中抽取可执行建议，合并进主文档。

### 2026-05-10 — 合并后的主方案要点

- **栈**：Tauri v2；Rust **Rope** 作单一事实源；**`pulldown-cmark` + 块级增量**；Worker / `requestIdleCallback`；禁止 Electron 与 React/Vue 等重型 UI 壳。
- **红线**：延迟、内存、包体、帧率等可量化目标见主文档 §1。
- **依赖**：npm 包数量设上限；生产 bundle 尽量薄；可选 **CodeMirror 6** 仅作编辑层且受预算约束。
- **工程方法**：吸收 Qwen 的指标与去依赖纪律；吸收 Grok 的 Rope/解析/叠加层/中文 IME 与可选 CM6 等思路。

### 2026-05-10 — 产品形态（已定）

- **明确不分栏**：不提供左编右预览、双栏或编辑/预览分屏等正式功能；**仅一体化编辑表面**（类 Typora）。性能验证依赖一体化壳 + 夹具与自动化测试，**不以分栏作为过渡或交付 UI**。  
- MVP 与「明确不做」列表已按此红线同步（见主文档 §4、§6）。

### 2026-05-15 — 视口切片滚动修复

- **问题**：大文档视口模式下向下滚动，下方格式化内容不可见。
- **原因**：上下 spacer 按 UTF-8 字节比例估算，与真实 DOM 高度之和不等于 `scrollHeight`。
- **修复**：上 spacer 与 `scrollTop` 对齐；下 spacer 在布局后按 `scrollHeight − top − middle` 写入；`requestAnimationFrame` 滚动重绘；`#editor-overlay` 使用 `min-height` 对齐源码高度。Vitest 增至视口相关用例。

### 2026-05-15 — 逐行叠加层与文末光标

- **问题**：视口切片与 pulldown 块高仍易错位；修复后又出现「能滚到底但光标无法落在文末」。
- **决策**：叠加层改为 **`renderMarkdown()` 逐行渲染**（每行 `.md-line`）；`parse_blocks` 仍调用并缓存，供后续增量。
- **光标 / 滚动**：叠加层 `height` / `min-height` 锁定为 `#editor-source.offsetHeight`；标题等改为 `font-size: inherit` + 加粗，避免叠加层虚高。
- **涉及文件**：`src/editor.ts`、`src/renderer.ts`、`src/styles.css`；`src/viewport-overlay.ts` 保留工具函数与单测。
