# MarkPad — Windows 打包说明

面向需要在 Windows 上产出**安装包**或**免安装 exe** 的贡献者与发布人员。命令以**项目根目录**为当前工作目录。

---

## 1. 环境要求

| 项 | 说明 |
|----|------|
| Node.js | 已安装并在 `PATH` 中（脚本会调用 `npm`） |
| Rust stable | `cargo` 在 `PATH` 中 |
| WebView2 | **最终用户**机器需有 WebView2 Runtime；本机开发/打包通常已满足 |
| Windows 组件 | NSIS / WiX 等由 Tauri CLI 按需提示或拉取；若 MSI 失败请根据 CLI 日志安装缺失项 |

---

## 2. 推荐方式：只运行一个批处理（勿重复手清）

| 脚本 | 作用 | 成功后产物精简 |
|------|------|------------------|
| [`scripts/build-non-standalone.bat`](../scripts/build-non-standalone.bat) | `tauri build --bundles nsis msi` | **自动**调用同目录 `clean-pack-release.bat`，`release` 下**只保留** `bundle\`（安装介质） |
| [`scripts/build-portable-no-installer.bat`](../scripts/build-portable-no-installer.bat) | `tauri build --no-bundle` | **自动**调用 `clean-pack-release.bat`，`release` 下**只保留** `*.exe` 与 `*.dll` |

两个脚本都会在调用 Tauri 前设置 **`CARGO_TARGET_DIR`** 为项目根下的 **`output`**。  
在此配置下，Cargo 与 Tauri **分工两个平级目录**（这是正常现象，不是脚本写错）：

```text
<项目根>\output\
├── release\          ← Cargo Release（便携 exe / dll）
│   ├── MarkPad.exe
│   └── *.dll
└── bundle\           ← Tauri 安装包（与 release 平级，不在 release 里面）
    ├── nsis\         ← NSIS 安装向导（.exe）
    └── msi\          ← WiX/MSI 安装包（.msi）
```

**无需**在成功执行上述任一脚本后再单独运行 `clean-pack-release.bat`。若你**没有**通过这两个脚本打包（例如自行执行 `npm run tauri build`），则不会自动精简，此时可自行执行：

```bat
scripts\clean-pack-release.bat "<项目根>\output\release" portable
```

或（安装包构建完成后）：

```bat
scripts\clean-pack-release.bat "<项目根>\output\release" bundle-only
```

将 `release` 换成你实际的 Cargo release 目录（见下节「回退路径」）。

---

## 3. 若产物出现在 `src-tauri\target\release`

脚本会尽量把 `CARGO_TARGET_DIR` 传给 `npm` / Tauri。若因环境异常导致 **Cargo 仍写入默认目录**，批处理在构建成功后会**检测**可执行文件或 `bundle` 是否出现在 `output\release`；若不在，会**回退**到：

```text
<项目根>\src-tauri\target\release\
```

并对该目录执行同样的精简逻辑，同时在控制台输出**警告**，便于你排查（例如 npm 版本、从非 CMD 启动导致的环境变量未传递等）。

---

## 4. 产物路径速查

| 类型 | 默认路径（`CARGO_TARGET_DIR=output` 时） |
|------|------------------------------------------|
| NSIS 安装向导 | `<项目根>\output\bundle\nsis\*.exe` |
| MSI | `<项目根>\output\bundle\msi\*.msi` |
| 免安装 exe | `<项目根>\output\release\MarkPad.exe` 及同目录 `*.dll` |

### NSIS 与 MSI 有何不同

| | **nsis\** 里的安装包 | **msi\** 里的安装包 |
|--|---------------------|---------------------|
| 格式 | 多为 **`.exe` 安装向导**（Nullsoft Installer） | **`.msi`**（Windows Installer / WiX） |
| 体验 | 常见「下一步」向导，适合个人分发 | 适合企业域策略、GPO、部分 IT 只认 MSI |
| 技术 | Tauri 用 NSIS 脚本打包 | Tauri 用 WiX 工具链打包 |
| 内容 | 都是安装同一套 MarkPad，装完效果类似 | 同上 |

两种选一种分发即可；`build-non-standalone.bat` 会同时生成两者。

简短备忘亦见：[`scripts/打包说明.txt`](../scripts/打包说明.txt)。

---

## 5. 与 `npm run tauri build` 的区别

在项目根直接执行 **`npm run tauri build`** 时，**不会**设置 `CARGO_TARGET_DIR`，也不会执行 `clean-pack-release.bat`。产物通常在 `src-tauri\target\release\`，且目录内会保留大量 Cargo 中间文件。适合本地调试；**对外发布**请优先使用本节所述批处理。

---

## 6. `clean-pack-release.bat` 使用说明

### 6.1 参数与默认值

在 **CMD** 中推荐写法（路径可省略，脚本会依次尝试 `<仓库根>\output\release` 与 `src-tauri\target\release`）：

```bat
scripts\clean-pack-release.bat
scripts\clean-pack-release.bat "" portable
scripts\clean-pack-release.bat "E:\projects\MarkPad\output\release" bundle-only
```

- **第 1 参数**：`release` 目录；省略时自动探测上述两个路径之一。  
- **第 2 参数**：`bundle-only` 或 `portable`；**省略时**：若该 `release` 下存在 **`bundle\`** 则默认 **`bundle-only`**，否则 **`portable`**（避免误删安装包）。  
- **第 3 参数**：传 **`nopause`** 时结束后不暂停（`build-*.bat` 内部调用时已带上，避免打断自动打包）。

在资源管理器中 **双击** 本脚本：会使用默认目录与默认模式，并在结束前 **暂停** ，便于查看输出（以前若未传参会瞬间报错退出，看起来像「闪退」）。

### 6.2 模式摘要

| 模式 | 行为摘要 |
|------|----------|
| `bundle-only` | 删除 `release` 下除 `bundle\` 外的根目录文件与子目录；在 `bundle\` 内删除常见 NSIS/WiX 中间文件 |
| `portable` | 删除 `bundle\`、deps/build 等大目录及链接副产物；根目录仅保留 `*.exe`、`*.dll` |

由两个 `build-*.bat` **在构建成功后自动调用**（并带 `nopause`），一般无需手工跑。若 `release` 仍约 **1 GB+**，请查看脚本是否打印 **`deps` / `build` still present**——常见原因是 **该目录下 exe 正在运行** 或文件被占用，请先退出应用再执行一次清理。

自动化环境可设置环境变量 **`CLEAN_PACK_NO_PAUSE=1`** 以去掉末尾暂停（与 `nopause` 二选一即可）。

## 7. 故障排查

1. **构建失败**：根据控制台与 Tauri 日志处理；失败时脚本**不会**执行清理。  
2. **构建成功但目录仍很乱**：查看是否出现「回退清理目录」警告；确认是否用了仓库内的 `scripts\build-*.bat` 且同目录存在 `clean-pack-release.bat`。  
3. **缺少 `clean-pack-release.bat`**：脚本会报错并退出；请从仓库恢复完整 `scripts` 目录。  
4. **双击脚本「闪退」**：请使用更新后的脚本（无参时有默认目录、结束会暂停）；或打开 CMD 执行并查看报错。  
5. **清理后仍很大**：确认无进程占用 `output\release` 下的 exe；根据 §6.1 选对 `portable` / `bundle-only`（有 `bundle\` 时不要误用 `portable` 否则会删掉安装包目录）。
