# 极简 Markdown 编辑器 — 开发方案

> 本文在初版讨论稿基础上，**综合** `开发方案讨论稿-qwen版.md` 与 `开发方案讨论稿-grok版.md` 中可复用的思路，形成单一主文档；**不是**简单二选一，而是取两者之长、显式处理冲突点。  
> 总目标不变：**类 Typora 的专注写作体验**，但以**响应速度、资源占用、可维护性**为硬约束。

---

## 0. 两稿中已吸收的主要观点

| 来源 | 吸收进主方案的内容 |
|------|-------------------|
| **Qwen 版** | 可量化红线（延迟、内存、包体、帧率）；**拒绝 Electron 与 React/Vue 等重型 UI 框架**；**虚拟块 + 懒 DOM**、生产 bundle 尽量薄；WASM 解析为中长期方向；MVP 功能做减法、用「性能–功能」表控范围。 |
| **Grok 版** | **Rust 侧 Rope + 与编辑区同步**作为「单一事实源」；**`pulldown-cmark` + 块级增量**；**Worker + `requestIdleCallback` + 视口±缓冲**；**CodeMirror 6 作可选编辑表面**；**中文输入法**与跨平台 WebView 早测；**源码 + 样式叠加**的一体化实现思路；单文件内搜索、最近文件等**低依赖高价值**能力。（原稿中「先分栏再一体化」未采纳，见下条。） |

**冲突点与裁定**（见 §4 产品形态）：

- **界面形态**：**明确不分栏**——不提供「左侧编辑 / 右侧预览」或任何持久双栏写作界面；**只有一体化编辑表面**（类 Typora：同一区域编辑即所见）。性能验证通过 **一体化壳 + 基准夹具 / 自动化测试与 profiling** 完成，**不以分栏模式作为交付或过渡 UI**。  
- **是否引入 CM6**：**不默认**；仅当自研选区/撤销与 WebView 组合风险过高时，**以包体与主线程预算为约束**引入 CM6 作「编辑层」，仍禁止整页 React 应用壳。

---

## 1. 红线指标（立项即验收基准）

| 指标 | 目标（讨论值，可按机型微调） |
|------|------------------------------|
| 输入响应 | ≤ 8ms（连续输入；与 16ms/95 分位可同时取样，取更严者验收） |
| 常驻内存 | Win ≤ 60MB / macOS ≤ 45MB（典型写作文档） |
| 冷启动到可输入 | ≤ 0.8s（可与 Grok 稿中 300ms 理想值并存：前者保底、后者Stretch） |
| 安装包体积 | ≤ 15MB |
| 长文档滚动 | ≥ 55fps，丢帧可控 |
| 打开大文件 | 例：10MB 级 MD 可编辑、无明显卡顿；再大文件用**惰性加载 / mmap**（Rust 侧）与降级策略 |

---

## 2. 设计原则

| 原则 | 说明 |
|------|------|
| **性能优先** | 架构决策服从延迟与内存；新增功能须过压测与「性能–功能」评审 |
| **功能做减法** | 只做多数场景刚需；扩展能力可延后或以 `--enable-features`、实验分支交付 |
| **依赖克制** | 无 Electron；无 React/Vue/Angular 与重型全局状态方案；**npm 依赖数量设上限**（如 ≤15 个量级，具体立项时写死），优先标准库与小而稳的包 |
| **渲染可预测** | DOM 变更块级、可测；禁止默认「全文替换 innerHTML」 |

---

## 3. 技术选型（融合栈）

| 层级 | 选型 |
|------|------|
| **壳** | **Tauri v2**（Rust + 系统 WebView），文件与系统集成走 Rust |
| **文本核心（推荐）** | Rust **`ropey`（或同类）Rope** 作为**单一事实源**：高效插入删除、与撤销栈协同；大文件可结合 **mmap / 分块加载** 策略 |
| **前端主体** | **TypeScript + 原生 DOM**（默认）；构建开发期可用 Vite，生产 **`tsc` + 精简 bundle** |
| **编辑表面（可选）** | 自研块映射 + Selection；若工期或正确性风险过高，**允许引入 CodeMirror 6（Markdown 模式 + 最小扩展）**，须审计包体与主线程开销 |
| **解析** | Rust：**`pulldown-cmark` + 块级增量**（仅解析变更块及相邻边界）；JS 侧仅作过渡或 fallback；中长期可将热点路径改为 **Rust 增量解析输出 WASM**（配合 `wasm-opt`、按需加载） |
| **一体化 UX（推荐路径之一）** | **底层仍为 Markdown 源码**，格式化通过 **叠加层 / 块级装饰** 呈现 Typora 式体验，避免「整文档富文本 DOM」失控 |

**备选（长期）**：纯 Rust + egui/slint——理论占用更低，一体化编辑成本高，**首版不推荐**。

---

## 4. 产品形态与交付节奏

- **体验目标**：类 Typora **一体化**（编辑即所见）。  
- **红线**：**不分栏**——从首版到后续迭代，**不**提供双栏、分屏预览、独立「源码面板 vs 预览面板」等布局作为正式功能（避免路径分叉与维护两套交互）。  
- **工程节奏**：在**一体化界面**内迭代 **Rope ↔ 前端同步**、块级增量、Worker、虚拟视口；指标通过夹具压测、Profiler、回归测试验收，**不**依赖临时分栏产品形态。  

---

## 5. 渲染与数据流（摘要）

```
输入 → Rust Rope 提交变更 → 块级增量解析（pulldown-cmark / 日后 WASM）
     → AST Diff → 仅更新变更块及相邻块
     → 视口裁剪（可视 ± N 屏）→ DocumentFragment / 细粒度 DOM 更新
     → Worker：非关键路径解析与排队；requestIdleCallback 消化低优先级工作
```

- **代码高亮**：仅视口内与刚变更块；避免全文 Lang 扫描。  
- **光标/选区**：与 Rope 偏移一致；自动化测试覆盖边界；语义可对齐 CM6 行为（即使未引入 CM6）。

---

## 6. MVP 范围（建议）

**保留（第一可用版本）**

- 本地打开/保存、UTF-8、自动保存；**最近文件**（本地存储）。  
- **仅一体化界面**，不提供分栏模式。  
- 基础语法：标题、列表、粗斜体、代码块、引用、链接、图片（本地路径）。  
- 撤销/重做（建议 ≥ 5000 步量级目标）、常用快捷键。  
- 跟随系统深/浅色，**固定一套浅色 + 一套深色**，不做主题商店。  
- **单文档内搜索**（Rust 侧字符串/Rope 扫描，避免前端遍历巨型 DOM）。  
- **导出**：复制 Markdown、复制纯文本；**可选**：复制 HTML 片段（不落盘、不引入重型排版引擎）。  

**明确不做（首版勿扩散）**

- **分栏 / 双栏 / 编辑区与预览区分屏**（与 §4「不分栏」红线一致）  
- 云同步、账号、插件市场  
- 数学公式、Mermaid、流程图、复杂表格 WYSIWYG  
- 多标签页、侧边栏大纲（可列为 V1）、**跨仓库全局搜索**  
- 主题自定义市场、打印预览、PDF/Word 导出  
- 重型「导出 HTML 文件 / PDF」依赖链（wkhtmltopdf 等）——单独立项再加

## 7. 阶段与周期（参考）

| 阶段 | 周期（参考） | 焦点 |
|------|----------------|------|
| Phase 0 验证 | 1–2 周 | Tauri + Rope + 块级增量 + Worker；10 万行级夹具压测 |
| Phase 1 管道 | 4–5 周 | 文件 I/O、虚拟视口、一体化编辑表面与渲染管线打通 |
| Phase 2 性能 | 3–4 周 | AST Diff、光标/IME、泄漏与帧率专项 |
| Phase 3 稳定 | 2–3 周 | 快捷键、撤销栈、打包裁剪、跨平台回归 |
| Phase 4 压测发布 | 2 周 | 真实文档集、指标验收 |

## 8. 风险与对策（合并两稿）

| 风险 | 对策 |
|------|------|
| 一体化 + 自研光标错位 | 一体化界面内充分迭代；选区自动化测试；必要时 CM6 仅作编辑层；开发者可用的调试开关（非面向用户的分栏） |
| **中文输入法**（Win/macOS） | 早期专项测试；composition 事件与 Rope 提交顺序固化 |
| WASM 体积与兼容 | JS/Rust 双路径 fallback；`wasm-opt`；按需加载 |
| WebView 差异 | 三端矩阵；CI 基础回归（可先从 Win + macOS 开始） |
| 功能蔓延 | 「性能–功能」表 + 依赖数上限 + 实验开关 |

---

## 9. 待拍板（少量）

1. **Stretch 指标**：是单独列冷启动 300ms 等为优化目标（非首版强制）。  
2. **首版平台优先级**不与 Linux 是否同期。  
3. **开源协议**与分发策略。  
4. **遥测**：匿名性能直方图默认关闭与否。  
5. **单文件大小上限**与超限降级（如提示拆分、mmap 只读模式等）。

---

## 10. 小结

**方案融合后的核心**：**Tauri + Rust Rope 与块级增量管线为骨架**，**拒绝重型前端栈与功能蔓延**；**界面始终一体化、明确不分栏**；**从 Qwen 稿保留量化红线与 bundle 纪律**，**从 Grok 稿保留 Rope、解析栈、一体化叠加思路、IME 与可选 CM6**。在此骨架达标前，谨慎增加 MVP 条目。
